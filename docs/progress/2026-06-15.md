### Conceptos aprendidos

1. **OpenAPI**: estándar JSON/YAML para describir APIs REST, machine-readable
2. **Swagger UI**: interfaz web interactiva que permite probar endpoints desde el navegador
3. **Swashbuckle**: librería que genera el documento OpenAPI automáticamente inspeccionando controllers y DTOs
4. **Documentación dinámica**: Swagger no se escribe a mano, se regenera en cada request
5. **Schemas de DTOs**: Swagger documenta automáticamente tipos, formatos y restricciones de cada DTO
6. **Content-Type**: `application/json` es el estándar oficial; `text/json` y `text/plain` son variantes no estándar

### Problemas encontrados

- `Microsoft.OpenApi` v2 cambió el namespace de `Microsoft.OpenApi.Models` a `Microsoft.OpenApi`
- Swagger UI no cargaba por `UseHttpsRedirection` sin puerto HTTPS configurado → solución: condicional en development
- Los paths en OpenAPI usan `/api/Tasks` (con T mayúscula, del nombre del controller `[controller]`), no en minúscula como se esperaba intuitivamente
